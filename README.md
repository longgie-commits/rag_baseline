# RAG Baseline Project

这是一个轻量级、纯本地且基于开源模型的 **RAG (Retrieval-Augmented Generation，检索增强生成)** 演示与基线测试项目。它旨在演示如何不依赖任何昂贵的商业 API（如 OpenAI），而仅利用本地运行的模型从本地知识库中进行准确的事实问答。

## 项目架构与原理

该项目的核心由两个开源大模型分工完成：

1. **图书管理员：检索与向量化模型 (`all-MiniLM-L6-v2`)**
   - **特点**：体积小巧，计算极快。
   - **作用**：负责阅读指定的参考书籍（如 NASA 手册），将大段的文本进行切分成段（Chunking），并转化成高维向量（Embeddings）。当我们提出问题时，它也能瞬间将问题向量化，并在 FAISS 库中计算距离，精准挑出最相关的段落作为参考资料。
2. **知识解说员：生成模型 (`EleutherAI/gpt-neo-1.3B`)**
   - **特点**：基于 GPT 架构的自回归自然语言生成模型。
   - **作用**：扮演“阅读理解者”的角色。它本身不需要把所有书都背下来，而是接收检索模型找到的“相关段落原文（Context）”结合“用户提出的问题（Query）”作为上下文，当场生成一段通顺、总结性的人类语言来回答问题。

## 项目目录结构

```text
rag_baseline/
├── .venv/                   # Python 虚拟环境，包含所有的依赖库
├── data/                    
│   └── raw/                 # 存放原始知识库数据的地方 (例如 nasa_systems_engineering_handbook.pdf)
├── index/                   # 根据 PDF 自动生成的 FAISS 向量数据库与元数据记录
├── src/
│   ├── build_index.py       # 脚本一：读取数据 -> 切分文本 -> 生成向量 -> 构建并保存向量数据库
│   └── retrieve.py          # 脚本二：接收问题 -> 检索向量 -> 拼接 Prompt -> LLM 生成最终回答
├── run.bat                  # 一键启动的系统快捷菜单脚本
├── requirements.txt         # 项目依赖声明
└── README.md                # 项目文档（当前文件）
```

## 面向开发者的快速开始指南

项目提供了一个非常友好的整合启动脚本（`run.bat`），你可以在终端中直接输入调用或者在文件管理器双击运行它：

```powershell
.\run.bat
```

此时会弹出菜单交互，主要分为以下两个生命周期：

### 阶段一：构建知识库（Build Index）
- **终端选择**：`[1]`
- **何时操作**：当第一套环境刚刚搭建好，或者你在 `data/raw/` 中更换/更新了新的 PDF 文件时。
- **底层动作**：调用 `src/build_index.py` 解析文挡并在本地 `index/` 建立可以极速检索的 `faiss.index` 数据库。只需执行一次。

### 阶段二：启动问答交互（Start Retrieval）
- **终端选择**：`[2]`
- **何时操作**：主要日常操作，当你需要进行多次问答测试或者调试时选择。
- **底层动作**：调用 `src/retrieve.py` 加载 `index` 和 `gpt-neo-1.3B` 模型，进入终端对话模式。你可以重复输入 query 获取模型基于文档的专属回答。

## 注意事项
- 由于使用了大型生成模型，如果首次运行选择 2 时，`transformers` 缓存文件夹为空，可能需要在后台花较长时间自动拉取并下载 1.3B 的模型权重（几个 GB 左右），后续再次启动将直接从缓存读取，速度大幅提升。
- 受限于 `gpt-neo-1.3B` 的参数级，部分复杂逻辑推导可能会有局限性，但这作为 RAG 上下文拼装的基线验证已经完全足够。
